REA 逆向工程实战 第2期：10 分钟装好——把 REA 接进你的 AI 助手

适合人群：看完了第 1 期，准备动手的开发者

阅读时间：约 8 分钟

往期回顾：[第1期：认识 REA——让 AI 当你的"软件解剖师"](01-第1期-认识REA.md)

本期导读

装开发工具最让人没底的，不是步骤难，而是不知道它偷偷改了你电脑上哪些文件。这一期我们把安装过程拆成看得见的五步，每一步都说清楚"它要动什么、你该看到什么"。另外会重点讲两个真实存在的坑：一个是 Node.js 版本要求卡得很具体，另一个是装完之后怎么确认真的生效了——很多人卡在这一步，以为是没装上。

一、为什么建议你先看完再动手

先说一个真实情况：npx rea-agents setup 这条命令会修改你的 AI 助手配置文件，而且支持好几种助手。

它有备份机制，不是危险的。但你可能不想在没搞清楚之前就让它改文件——尤其是你已经在用 Claude Code 或 Cursor 做正经项目的时候。

所以这一期的顺序是：先看清楚它会动什么 → 再执行 → 最后验证。整个过程大约 10 分钟。

二、装之前：先确认三件事

2.1 第一件事：你的 Node.js 版本够不够

这是最容易踩的坑，而且报错信息往往不直接告诉你原因。REA 官方要求是：

| 可以用的版本 | 具体小版本要求 |

|-------------|--------------|

| Node.js 22.x | 必须 ≥ 22.19 |

| Node.js 24.x | 必须 ≥ 24.11 |

| Node.js 26 及以上 | 无额外限制 |

⚠️ **注意**：注意看第一列和第二列的差别。你装了 Node.js 22 不代表就能用——如果小版本是 22.18，刚好差一点，是会失败的。这类"大版本对、小版本不对"的情况最浪费时间，因为你会反复怀疑是不是别的地方出问题了。

检查一下你现在的版本，打开终端（Windows 用 PowerShell 或 Git Bash，macOS 用终端）输入：

 node -v 

看到的结果如果是 v22.19.0、v24.11.0 这种，就没问题。如果是 v22.18.0 或者 v20.x，先去 Node.js 官网升级。

顺手也确认一下 npm 在不在（它是 Node.js 自带的包管理工具，负责下载安装 REA）：

 npm -v 

2.2 第二件事：你打算用哪个 AI 助手

REA 的安装程序支持主流的命令行 AI 助手，包括 Claude Code、Codex、Cursor、Gemini CLI、Grok Build 等。

📌 **术语卡**

**命令行 AI 助手** = 在终端里跑的编程助手，能读你的代码、执行你的命令。

**打个比方**：就像你旁边坐了个实习生，你说"帮我看看这个函数"，他就真的去翻你的代码文件，而不是只在聊天框里凭空回答。

图下解读：这张图列的是官方支持的几种命令行助手。看最下面那张卡——只要你用的助手支持本地 MCP 服务，就算不在这个列表里，也能通过手动注册的方式用上 REA。所以不用担心自己用的工具太冷门。

如果你还没用过上面任何一个，那这一期后面的 MCP 部分可以先跳过，直接看第五节「终端模式」——那部分不依赖任何 AI 助手，装完就能用。

2.3 第三件事：想清楚要不要让它自动装 Hopper

安装过程中，程序可能会问你要不要自动安装 Hopper（一个商业的反汇编软件，用来看原生二进制文件）。

这里给你一个明确建议：第一次先选不装。

原因很简单——第 3 期我们做的第一个实验是分析 JavaScript 应用，完全不需要 Hopper。等你确实要分析原生二进制了（第 5 期），再回来装也不迟。少装一个东西，就少一个出错的可能。

三、正式安装：五步走

图下解读：这张图里有三个判断点（菱形框），我建议你重点看中间那个「同意备份配置」——这一步是你最后一次说"不"的机会，点否就完全不会动你的文件。最后一个菱形「让它列一下有哪些工具」是验证环节，很多人跳过这步，结果用了半天才发现压根没连上。

第 1 步：运行安装命令

打开终端，输入：

 npx rea-agents setup 

📌 **术语卡**

**npx** = Node.js 自带的一个命令，用来「临时下载并运行」一个包，不用先手动安装。

**打个比方**：就像你想试吃一种零食，不用先买一大袋回家，直接在超市拿一小包尝一口。

第一次运行会花一点时间下载，耐心等它出现选择界面。

第 2 步：选择你的 AI 助手

界面上会列出它检测到的助手。用方向键选择你要用的那个，回车确认。

如果你装了好几个，选你日常主要用的那个。后面想加别的，重新跑一次这条命令就行。

第 3 步：检查它打算改什么，然后批准

这一步是 REA 做得比较讲究的地方——它会先把计划中的变更列给你看，包括：要往哪个配置文件里加 MCP 服务、要备份哪些已有配置、要安装哪些工作流指引。

看清楚再回车。  如果列出的文件路径不是你预期的（比如它改的 Cursor 配置不是你当前用的那个），这里就停下来排查。

确认没问题后批准，它会自动完成三件事：备份已有配置、注册 REA 的 MCP 服务、安装匹配的工作流指引。

第 4 步：重启你的 AI 助手

这一步必须做，而且很多人会忘。MCP 服务是在助手启动时加载的，不重启的话，助手根本不知道 REA 已经装上了。

关掉，重新打开。

第 5 步：验证

重启之后，在 AI 助手里随便问一句：

 你现在有哪些可用的工具？ 

或者更直接一点：

 你能用 REA 做什么？ 

如果助手的回答里出现了 REA 相关的工具名（比如带 analyze、inspect 这类前缀的工具），说明装好了。

四、装完没生效？按顺序排查

图下解读：这张图的排查顺序是有讲究的——先看最简单的原因（没重启），再看配置有没有写进去，最后才怀疑版本。我见过太多人一上来就重装，结果问题只是没重启。按这个顺序来，八成的情况在前两步就能解决。

💡 **小提示**：REA 更新非常快，官方在常见问题里明确说「遇到错误时先更新」。所以排查到最后一步时，与其反复试，不如先跑一次更新命令，很可能问题在新版本里已经修掉了。

五、不想接 AI 助手？用终端模式

如果你暂时没有命令行 AI 助手，或者就想先自己试试，REA 提供完整的命令行（CLI）用法。

临时用一次（不用安装）：

 npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json 

把路径换成你要分析的应用目录。注意两点：路径要写绝对路径（从盘符或根目录开始的完整路径），Windows 上建议给路径加引号，比如 "D:/apps/example"。

经常用的话，装成全局命令更方便：

 npm install --global rea-agents rea --help 

装完之后，rea --help 会列出所有可用命令。以后就可以直接用 rea 开头了，不用每次都 npx。

两种模式怎么选

| 场景 | 推荐模式 | 原因 |

|------|---------|------|

| 想让 AI 帮你串起整个调查 | MCP（接助手） | 它能连续追问、自动决定下一步 |

| 只要一次性拿到结果 | CLI（终端） | 干净利落，输出 JSON 好处理 |

| 排查"到底装好没" | CLI（终端） | 不依赖助手，能快速确认 |

| 要写进自动化脚本 | CLI（终端） | 有明确退出状态码 |

图下解读：左边那张卡是"接进 AI 助手"的好处——它能连续追问、自己决定下一步查什么，适合你还不知道答案在哪儿的探索阶段。右边是终端模式——干净利落，输出能直接喂给脚本。我的建议是两个都留着：平时用 MCP 模式做调查，需要确认"到底装好没"或者要批量处理时，切回终端模式。

六、更新与卸载

REA 迭代很快，建议保持最新。

全局安装的 CLI：

 rea update 

用 npx 装的助手配置：

 npx rea-agents@latest setup 

⚠️ **注意**：更新完助手配置之后，**记得再重启一次 AI 助手**——和第 4 步是一个道理。

卸载方法、以及手动注册 MCP 的完整说明，在官方的《安装与设置》文档里，这里不展开，因为大多数人暂时用不上。

📝 本期小结

1. 装之前先查 Node.js 版本，要求卡到小版本（22.x 需 ≥22.19，24.x 需 ≥24.11），这是最高频的坑。

2. 安装就是一条命令：npx rea-agents setup，五步走完——运行、选助手、批准变更、重启、验证。

3. 装完必须验证：问助手"你有哪些工具"，看不到 REA 的工具就说明没连上，回头按第四节的流程图排查。

速查表：

| 你要做什么 | 命令 / 动作 |

|-----------|------------|

| 检查环境 | node -v 看小版本是否达标 |

| 安装到 AI 助手 | npx rea-agents setup |

| 临时用一次 | npx -y rea-agents@latest analyze-javascript-application <路径> --json |

| 装成全局命令 | npm install --global rea-agents |

| 更新 | rea update 或 npx rea-agents@latest setup |

| 装完必做 | 重启 AI 助手 |

✍️ 动手练一练

这一期的练习只有一个动作，但非常重要：

把 npx rea-agents setup 跑起来，并且走完「批准」那一步之前就停下来。

具体做法：

1. 打开终端，运行 npx rea-agents setup

2. 一路走到「计划变更」那个界面

3. 截图保存它列出的变更内容（尤其注意：它要写入哪个配置文件、要备份哪些文件）

4. 确认没问题后再批准，走完剩下的步骤

为什么这么做：这张截图是你以后排查问题的第一手资料。等你哪天换了电脑、或者助手突然连不上了，你会想知道"当初它到底往哪儿写了什么"。

参考答案方向：正常情况下，变更清单里应该能看到 MCP 服务的注册信息、一个备份动作、以及工作流指引的安装位置。如果你看到它要动的文件完全在你的项目目录之外（比如动了某个你不认识的配置），停下来先搞清楚。
