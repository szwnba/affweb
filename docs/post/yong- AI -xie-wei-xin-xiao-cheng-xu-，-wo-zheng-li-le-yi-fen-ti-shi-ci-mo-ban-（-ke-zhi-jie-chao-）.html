用 AI 写微信小程序，我整理了一份提示词模板（可直接抄）

前几篇讲了上线流程、提审避坑、用AI 做出第一版，还有我踩过的 7 个坑。

很多人问：提示词到底怎么写？下面这6 类模板，是我现在固定会用的——按开发顺序排列，复制后把 [ ] 换成你的内容即可。

  1. 一次只让 AI 做一件事（拆需求、做一页、修一个 bug 分开问）

  2. 明确技术栈：微信小程序原生 / 是否用云开发

  3. 每条都加：不要编造不存在的微信API，不确定请标注

适用场景：只有一个模糊想法，还没想清楚页面和功能，就要AI 开始写代码。

模板（可直接抄）：

我要做一个微信小程序，请先帮我做需求拆解，不要写代码。

【项目信息】
- 项目名称：[项目名称]
- 目标用户：[谁会用]
- 核心问题：[解决什么问题]
- 主体类型：个人
- 技术栈：微信小程序原生

【请你输出】
1. 3～5 个核心功能（按优先级排序）
2. 页面清单（页面路径 + 每个页面做什么）
3. MVP 版本建议（第一版只做哪些）
4. 个人主体可能受限的功能提醒
5. 我需要补充确认的问题（最多 5 个）

要求：不要编造不存在的微信 API；不确定的地方请标注。

填好后的示例：

我要做一个微信小程序，请先帮我做需求拆解，不要写代码。

【项目信息】
- 项目名称：随手记一笔
- 目标用户：想快速记录日常开支的个人用户
- 核心问题：记账太麻烦，希望 3 秒内记完一笔
- 主体类型：个人
- 技术栈：微信小程序原生

【请你输出】
1. 3～5 个核心功能（按优先级排序）
2. 页面清单（页面路径 + 每个页面做什么）
3. MVP 版本建议（第一版只做哪些）
4. 个人主体可能受限的功能提醒
5. 我需要补充确认的问题（最多 5 个）

要求：不要编造不存在的微信 API；不确定的地方请标注。

注意：别一上来就说「帮我做小程序」——越模糊，AI 越容易乱猜（对应 7 坑之「提示词太糊」）。

适用场景：需求定了，要先搭页面骨架，再填功能和样式。

模板（可直接抄）：

请为微信小程序设计页面结构，先不要写复杂业务逻辑。

【页面】
- 路径：[pages/xxx/xxx]
- 页面名称：[页面名]
- 页面目标：[用户进来要完成什么]

【请你输出】
1. wxml 结构（区块划分：头部/列表/按钮等）
2. 需要的数据字段（js data 里放什么）
3. 需要的交互（点击、跳转、输入）
4. 关联页面（从哪来、跳去哪）
5. 验收标准（怎样算这个页面完成）

约束：
- 只改这一个页面相关文件
- 不编造 wx API
- 风格简洁，适合个人工具类小程序

填好后的示例：

请为微信小程序设计页面结构，先不要写复杂业务逻辑。

【页面】
- 路径：pages/index/index
- 页面名称：记账首页
- 页面目标：展示今日/本月支出汇总，并快速新增一笔

【请你输出】
1. wxml 结构（区块划分：头部/列表/按钮等）
2. 需要的数据字段（js data 里放什么）
3. 需要的交互（点击、跳转、输入）
4. 关联页面（从哪来、跳去哪）
5. 验收标准（怎样算这个页面完成）

约束：
- 只改这一个页面相关文件
- 不编造 wx API
- 风格简洁，适合个人工具类小程序

注意：一次只做一个页面，别让它同时改app.json + 三个页面（对应 7 坑之「一次改太多文件」）。

适用场景：页面结构有了，要实现某一个具体功能（如「新增一笔」「删除记录」）。

模板（可直接抄）：

请在现有微信小程序项目中实现【单一功能】。

【功能】
- 功能名称：[功能名]
- 所在页面：[pages/xxx/xxx]
- 用户操作：[用户点什么/输入什么]
- 期望结果：[完成后看到什么]

【验收标准】
1. 主路径可走通
2. 异常情况有提示（如输入为空）
3. 不破坏已有功能
4. 代码改动范围尽量小

【约束】
- 只实现这一功能，不要顺手重构其他页面
- 不要编造不存在的 wx API
- 如需新增字段，说明原因

完成后请告诉我：改了哪些文件、如何自测。

填好后的示例：

请在现有微信小程序项目中实现【单一功能】。

【功能】
- 功能名称：新增一笔支出
- 所在页面：pages/add/add
- 用户操作：输入金额和备注，点击保存
- 期望结果：保存成功并返回首页，首页列表出现新记录

【验收标准】
1. 主路径可走通
2. 异常情况有提示（如金额为空）
3. 不破坏已有功能
4. 代码改动范围尽量小

【约束】
- 只实现这一功能，不要顺手重构其他页面
- 不要编造不存在的 wx API
- 如需本地存储，优先 wx.setStorageSync（请确认用法）

完成后请告诉我：改了哪些文件、如何自测。

注意：每条提示词末尾加「验收标准」，AI 输出会更可用；你要当 QA 自己点一遍。

适用场景：运行报错、按钮无效、真机和模拟器表现不一致。

模板（可直接抄）：

我的微信小程序有一个 Bug，请帮我定位并修复。

【问题描述】
- 现象：[看到了什么]
- 期望：[应该怎样]
- 复现步骤：
  1. [步骤1]
  2. [步骤2]
  3. [步骤3]

【环境】
- 微信开发者工具 / 真机：[哪个有问题]
- 基础库版本：[如有]
- 报错信息（完整粘贴）：
[粘贴报错]

【约束】
- 最小改动修复，不要重写整个项目
- 不要编造 wx API
- 修复后说明根因 + 我如何验证

如果信息不足，先列出还需要我提供什么，不要猜。

填好后的示例：

我的微信小程序有一个 Bug，请帮我定位并修复。

【问题描述】
- 现象：点击「保存」后没有任何反应
- 期望：保存成功并返回首页
- 复现步骤：
  1. 打开新增页
  2. 输入金额 20
  3. 点击保存

【环境】
- 真机有问题，模拟器正常
- 报错信息（完整粘贴）：
TypeError: Cannot read property 'amount' of undefined

【约束】
- 最小改动修复，不要重写整个项目
- 不要编造 wx API
- 修复后说明根因 + 我如何验证

注意：报错信息、复现步骤越完整越好；别只说「坏了帮我修」（对应7 坑之幻觉 API）。

适用场景：功能差不多做完了，提审前检查隐私、授权、类目、个人主体限制。

模板（可直接抄）：

请对我的微信小程序做合规检查（个人主体），先不要大改代码，先出检查报告。

【项目信息】
- 名称：[小程序名]
- 简介：[简介]
- 类目：[已选类目]
- 主体：个人

【当前功能概述】
[简述做了什么]

【请你检查并输出】
1. 类目与实际功能是否一致
2. 个人主体是否有明显受限功能（社交/金融/电商等）
3. 是否使用用户数据/权限（昵称、手机号、位置等）
4. 是否缺少隐私政策/用户协议/授权说明
5. 是否有「开发中」占位或不可用按钮
6. 提审前必须修改项（按优先级排序）

要求：结合微信个人小程序常见审核点；不确定的标注「需查官方文档」。

- 类目：工具-记账

用户可新增/查看/删除本地记账记录，无社交、无支付。

3. 是否使用用户数据/权限
4. 是否缺少隐私政策/用户协议/授权说明
5. 是否有「开发中」占位或不可用按钮

要求：结合微信个人小程序常见审核点；不确定的标注「需查官方文档」。

注意：AI 很少主动补隐私页；这篇检查项要你自己过一遍（对应提审被拒高频坑）。

适用场景：准备上传代码、提交审核前的最后一轮检查。

模板（可直接抄）：

我要提交微信小程序审核，请按提审标准帮我做最后一轮自查。

【项目】
- 名称：[小程序名]
- 主体：个人
- 核心路径：[进入→操作→结果]

【请你输出 checklist】
请逐项判断：通过 / 风险 / 需修改，并给出修改建议：
1. 主功能是否可用（无死按钮、无占位页）
2. 名称/简介是否如实描述
3. 类目是否匹配
4. 隐私与授权是否齐全
5. 真机测试建议（我应点哪些路径）
6. 是否建议删减功能以提高通过率

最后给：提审前 10 分钟行动清单（按顺序）。

填好后的示例：

我要提交微信小程序审核，请按提审标准帮我做最后一轮自查。

【项目】
- 名称：随手记一笔
- 主体：个人
- 核心路径：打开首页 → 新增一笔 → 保存 → 首页看到记录 → 删除记录

【请你输出 checklist】
请逐项判断：通过 / 风险 / 需修改，并给出修改建议：
1. 主功能是否可用
2. 名称/简介是否如实描述
3. 类目是否匹配
4. 隐私与授权是否齐全
5. 真机测试建议
6. 是否建议删减功能

最后给：提审前 10 分钟行动清单（按顺序）。

注意：模板不能代替真机自测——清单打勾后，自己再用手机走 3 遍主路径。

好提示词= 说清楚目标 + 写清约束 + 给出验收标准。AI 负责加速，你负责方向和验收。
